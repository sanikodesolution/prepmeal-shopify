Meal Prep & Meal Plan Shopify 2.0 Theme — Version 1.0

Prep Meal – Meal Prep & Meal Plan Shopify Theme

Thank you for purchasing Prep Meal. Your support is truly appreciated! This documentation will help you install, configure, and fill the theme with your own menu and content — no developer required.

Prep Meal is a Shopify Online Store 2.0 theme built for weekly meal-prep businesses: meal plans with a slot-based box builder, a weekly rotating menu, a delivery-area checker with a live map, gift cards, private-chef bookings, and a full set of editable sections.

Theme Features:
  • 31 ready JSON templates (home, meal plans, products, contact, delivery, gift cards and all Shopify system pages)
  • 85 sections and 58 snippets — every section editable in the theme editor
  • Meal plans in 5, 6, 7, 10 and 15 plate variants
  • Slot-based “Build your box” with 5-plate / 10-plate discount tiers
  • Weekly menu with hover previews, nutrition facts and meal details
  • Metaobject driven content (meal plans, FAQ, testimonials, steps, delivery zones) with block fallback
  • Delivery-area checker with town/ZIP search and Leaflet map
  • Gift card purchase flow with recipient, delivery date and message
  • Private chef experience page with enquiry form
  • Ajax cart drawer, predictive search, quick order list
  • GSAP scroll animations with reduced-motion support
  • Cart drawer, filters, localization and customer account pages included
  • Translation-ready locales, accessible markup, lazy-loaded imagery
  • Well documented

Theme Features

Prep Meal is not a generic store theme with a meal section bolted on. The whole flow — plan, build, order, deliver — is built into the theme.

Requirements

  • Shopify plan: Basic or higher. Online Store 2.0 themes require a plan that includes the theme editor.
  • Theme version: Online Store 2.0 (JSON templates). Do not install on a vintage 1.0 store.
  • Products: A product per meal plan (for example 5-meal-plan) whose variants are the individual meals.
  • Optional: A gift card product, and a Shopify plan that supports gift cards, for the gift card page.
  • No apps required. Every feature — box builder, delivery checker, gift card flow — ships in the theme.
  • Browser support: Chrome, Firefox, Safari, Edge (latest two versions), iOS Safari and Chrome for Android.
No coding needed. Install the theme, connect your products and metaobjects, and fill the sections in the theme editor. Code editing is only required if you change the design system itself.

Package Contents

The download package contains:

  1. prepmeal-shopify.zip — the installable theme (upload this in Shopify admin)
  2. documentation — this help file (open docs/index.html)
  3. CONTENT-GUIDE.md — a short, non-technical content entry guide you can hand to the client

Inside the theme the folder structure is:

  1. assets/ — CSS, JavaScript, images, icons and SVG files
  2. blocks/ — theme app blocks
  3. config/ — settings_schema.json (settings definitions) and settings_data.json (saved values)
  4. layout/ — theme.liquid and password.liquid
  5. locales/ — translation files for all storefront strings
  6. sections/ — all page sections, including the cm-* meal-prep sections
  7. snippets/ — reusable partials (cards, icons, price, media)
  8. templates/ — JSON templates for every page type

Theme Installation

Option A — Upload the ZIP (recommended for first install):

  1. In Shopify admin go to Online Store → Themes.
  2. Click Add theme → Upload zip file and choose prepmeal-shopify.zip.
  3. Wait for the theme to upload, then click Customize to preview it.
  4. When you are happy, click Publish to make it the live theme.

Option B — Shopify CLI (recommended for development):


# Log in to the store you develop against
shopify theme dev --store your-store.myshopify.com

# Push all files to a new unpublished theme
shopify theme push --store your-store.myshopify.com --unpublished

# Later: push only the files you changed
shopify theme push --store your-store.myshopify.com --theme 123456789 --only sections/cm-build-box.liquid

After installing, do these four things in order:

  1. Upload your logo and favicon in Theme settings → Logo.
  2. Create the menus under Content → Menus (main menu, footer menu) and select them in the header and footer sections.
  3. Create your metaobject definitions and entries (see Metaobjects).
  4. Assign the meal plan templates to your pages and products (see Templates & Pages).
Keep a backup. Use Online Store → Themes → … → Duplicate before you edit the live theme, so you can always roll back.

Theme Structure

The layout file loads the global design tokens, the font faces and the page chrome. Every content section is loaded by its own JSON template.


<!doctype html>
<html class="js" lang="{{ request.locale.iso_code }}">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <link rel="canonical" href="{{ canonical_url }}">

  <!-- Fonts: body + heading -->
  <link href="https://fonts.googleapis.com/css2?family=Jost...&family=Plus+Jakarta+Sans...&display=swap" rel="stylesheet">

  <!-- Global behaviour -->
  <script src="{{ 'constants.js' | asset_url }}" defer="defer"></script>
  <script src="{{ 'pubsub.js' | asset_url }}" defer="defer"></script>
  <script src="{{ 'global.js' | asset_url }}" defer="defer"></script>
  {%- render 'gsap-animations' -%}

  {{ content_for_header }}
  {{ 'base.css' | asset_url | stylesheet_tag }}
</head>
<body class="gradient">
  {% section 'announcement-bar' %}
  {% section 'header' %}
  <main id="MainContent">{{ content_for_layout }}</main>
  {% section 'cm-footer' %}
  {% section 'cart-drawer' %}
</body>
</html>

How a page is assembled: each file in templates/ is a JSON map of sections. Shopify renders those sections in the order listed in the template, and each section renders its blocks. That means you can reorder, duplicate or remove a section on one page without touching another page.


{
  "sections": {
    "mp_page": { "type": "cm-meal-plan-page", "settings": { "plan_label": "5 Meal Plan" }, "blocks": { } }
  },
  "order": ["mp_page"]
}

Fonts Used

By default the theme loads these Google Fonts:

  • Jost — body text (400, with bold and italic variants)
  • Plus Jakarta Sans — headings (700)

The font link is in layout/theme.liquid:


<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Jost:ital,wght@0,400;0,500;0,600;0,700;1,400&family=Plus+Jakarta+Sans:ital,wght@0,500;0,600;0,700;0,800;1,500&display=swap" rel="stylesheet">

The CSS variables that every section uses are defined in the :root block of the same file:


:root {
  --font-body-family: "Jost", sans-serif;
  --font-body-style: normal;
  --font-body-weight: 400;
  --font-body-weight-bold: 700;

  --font-heading-family: "Plus Jakarta Sans", sans-serif;
  --font-heading-style: normal;
  --font-heading-weight: 700;

  --font-body-scale: 1;
  --font-heading-scale: 1.1;
}
Important: the heading font is set directly in layout/theme.liquid. The Heading font picker in Theme settings loads the font file, but the visible heading font comes from --font-heading-family. To change headings reliably, change both — the picker for the file, and the variable for the rendered font.

To use a completely different typeface, replace the Google Fonts link, then update --font-body-family and --font-heading-family. Section CSS reads those variables through --prep-font and --prep-display in assets/prep-content.css.

Change the Location

The theme has no single “store address” field. Location data lives in five separate places on purpose: the map centre, the delivery towns, the kitchen pin, the footer address and the contact page. Change all five when you move the business, or a customer will see one city in the footer and a different city on the map.

There are no global location settings. Nothing under Theme settings controls the address, the map or the delivery towns. Every value is a section setting, so you change it on the page that renders it.

Step 1 — Change the kitchen position

Open the theme editor, go to any meal plan page (/pages/5-meal-plan … /pages/15-meal-plan), select the CM meal plan page section and scroll to Delivery checker: map.

  1. Set delivery_kitchen_lat to your new latitude.
  2. Set delivery_kitchen_lng to your new longitude.
  3. Set plate_kitchen_address to the address text you want shown, for example Waukesha, Wisconsin.
  4. Leave delivery_radius_km at 0 to auto-fit the zone circle to your farthest town, or set a fixed radius in km.

Latitude and longitude are decimal degrees, not degrees/minutes/seconds. Latitude is positive north of the equator, longitude is negative west of Greenwich — so a Wisconsin address is always lat positive and lng negative.

Get the numbers. Open Google Maps, right-click your exact building, and click the coordinates at the top of the menu to copy them. They paste as 43.1051, -88.3420 — the first number is latitude, the second is longitude.
Step 2 — Change the delivery towns

The checker needs one line per town. The format is Name|lat|lng|ZIP,ZIP — the ZIP column is optional but without it customers cannot search by postcode.


Hartland|43.1051|-88.3420|53029
Delafield|43.0608|-88.4037|53018
Waukesha|43.0117|-88.2315|53186,53188,53189
Pewaukee|43.0806|-88.2612|53072
  • Paste the list into Delivery towns (delivery_towns).
  • Leave the field empty to keep the packaged Hartland / Lake Country list. An empty field never means “no delivery areas” — it falls back to the built-in list.
  • Several ZIP codes for one town go in the fourth column separated by commas, with no spaces.
  • delivery_initial_chips controls how many towns show as buttons before “Show all”.

The plate map is a separate list with a different format, because it is a stylised map with its own pin table rather than a true street map:


Name|ZIP,ZIP|left%|top%|kitchen|lat|lng
  • left% and top% are positions on the stylised map canvas, from 0 (left/top edge) to 100 (right/bottom edge).
  • Add the word kitchen as the fifth column on the row that marks your base.
  • lat and lng (sixth and seventh columns) are optional. Towns that already exist in the theme's built-in coordinate table work without them; any town it does not recognise needs its own coordinates or it will not get a pin.
  • plate_zone_radius (22–34) sizes the ring around the kitchen and controls how far the map zooms out.
The plate map follows the kitchen settings. The stylised map reads delivery_kitchen_lat and delivery_kitchen_lng for its centre, so step 1 moves this map too. You do not need to edit the town coordinates when you move the kitchen — only when you add a town the theme has never heard of.
Step 3 — Change the map centre and HQ pin

On the product template, select the CM delivery map section.

  • center_lat, center_lng — where the map opens. Put this near the middle of your delivery area, not necessarily your kitchen.
  • zoom — 5 is a whole state, 14 is a few blocks. 9–11 suits a local delivery radius.
  • fit_to_pins — turn on to ignore the zoom and frame every pin automatically. Best when you add or remove towns often.
  • hq_lat, hq_lng, hq_address — the headquarters popup.

Each pin block is one delivery town with its own area, lat and lng. Add, edit or delete blocks to change which towns appear.

Step 4 — Change the text addresses

The map is only part of it. Update these so the written copy matches:


cm-footer        → Contact info block → Delivery area / address
cm-footer        → Contact info block → Order & delivery days
cm-footer        → Contact info block → Phone, Email
cm-contact-page  → contact_item blocks (address, phone, hours)
cm-meal-plan-page → delivery_heading, delivery_text
cm-meal-plan-page → plate_kitchen_address
announcement-bar → delivery message, if one mentions a city
Step 5 — Check it
  • Type a town into the checker on each plan page — the yes message names the right town
  • Type a ZIP code that should work — it matches the fourth column
  • Type a town you removed — you get the not-found message
  • The kitchen dot sits on your real building on the map
  • The delivery ring covers every town you deliver to
  • Footer and contact page show the new address, not the old one
  • Announcement bar and FAQ copy do not name the old city
Plan pages are separate sections. Each plan page (5, 6, 7, 10, 15) has its own copy of the cm-meal-plan-page section, so editing the towns on the 6-meal page does not change the 15-meal page. Repeat step 1–2 on every plan page, or copy the edited JSON template over the others.

Metaobjects

Metaobjects let you keep a long list — 20 meals, 40 FAQs, 30 reviews — outside the theme editor, then point a section at that list. The section setting is called Content source and it always shows the field label from the section schema, for example Meal plans (Metaobject).

How the fallback works
  1. If the Metaobject list selected in the section has entries, the section renders those.
  2. If the list is empty, the section renders its blocks instead.
  3. If both are empty, a short empty-state message is shown in the editor.

Because of this, a section never breaks when you switch modes — the blocks act as the built-in demo content.

Create a definition
  1. Go to Content → Metaobjects → Add definition.
  2. Set the Type to the exact name in the table below (for example meal_plan). The type cannot be changed later.
  3. Add each field with the exact field name and type shown below. Field names become the template accessors, so Short description must be named short_description.
  4. Enable the storefront access for each field you display.
  5. Add entries, set their status to Active, then select the list in the section.

Product Metafields

Individual meals are ordinary Shopify products. Nutrition and ingredient data comes from product metafields in the custom namespace, so the same numbers appear on the product page, the plan page and the box builder.

Build Your Box

cm-build-box turns the variants of one plan product into plates. Customers add plates to fill slots; when the slot requirement is met, the box is added to the cart as a single Ajax request.

How it works
  1. Each variant of the plan product becomes a meal card, using the variant title as the meal name and the variant image (or a packaged food image) as the photo.
  2. Every plate costs the variant price. Quantity controls appear once a plate is added.
  3. The box shows a running subtotal, the box discount, and the total.
  4. The checkout button stays locked until Plates needed before checkout (min_plates) is reached.
  5. Adding to the cart posts each selected variant with a Plan line-item property and opens the cart drawer.
Settings
Setting Default Notes
headingPlan titlePage heading, for example “10 Meal Plan”.
ledeDiscount explanationOne or two sentences above the grid.
product10-meal-planOn a product template the current product is used automatically.
min_plates5Plates needed before the button unlocks.
Discount tiers

The box displays two tiers, and both are display only — the cart charges the variant price:

Plates in the box Displayed rate Message
1 – 4—“N more plates to unlock 15% off.”
5 – 915%“15% unlocked. N more for 20% off.”
10 or more20%“You’ve unlocked the best rate: 20% off every plate.”
Wording matters. The theme does not apply a cart-level discount. If you advertise the 15% / 20% rates, configure an automatic discount in Shopify (Discounts → Create discount → Amount off order) with a minimum quantity, or reword the copy so it only describes the per-plate menu price. Never promise a discount that the cart does not apply.

Add, Update or Remove a Product

There are two kinds of product in this theme, and they behave differently: meal products (one dish) and plan products (5, 6, 7, 10 or 15 plates). A meal product feeds the menu lists and the cart lines. A plan product is the container the box builder or the plan page charges through.

Two kinds of product
Kind Example Template What it does
Mealperi-peri-chickenproduct (default)One dish. Carries nutrition metafields and the photo used in menus.
Plan6-meal-planproduct.6-meal-planContainer. Its variants are the ten dish names; its price is what the cart charges per plate.
Plan variants are dish names, not sizes. Every plan product has a single option called Meal whose values are the dish names. That is how the plan page turns each dropdown choice into a cart property such as Meal 1 = Butter Chicken…. Do not rename the option or convert it to S/M/L.
Add a new meal
  1. Products → Add product. Give it a name customers would say, for example Peri Peri Chicken with Roasted Potatoes & Carrots.
  2. Set Product type to Meal and the price to the per-plate price.
  3. Leave the template as product — only plan products use a suffixed template.
  4. Upload the dish photo. Crop it square (900 × 900); it is used as the menu card and the round plate.
  5. Fill the nutrition metafields: custom.calories, protein, carbs, fat, plus ingredients, allergens, diet_tags, reheat_instructions (see Product Metafields).
  6. Add it to whatever collection you use for browsing — the default theme links to meal-plans. Note this does not put the dish into the plan page dropdowns; those come from the plan product's variants.
  7. Publish it to the Online Store sales channel. A product saved as Active but not published is invisible on the storefront.

To also show the new dish as a block in a plan page menu list, open the plan page in the editor, select CM meal plan page, and add a Menu item block with the same Meal name as the plan variant. The name is the join key — if the block name and the variant title differ, that dish adds nothing to the cart.

Add a new dish to a plan's dropdowns

The dropdowns on a plan page are built from the plan product's variants, so adding a dish means adding a variant:

  1. Open the plan product, for example 6-meal-plan.
  2. In the Meal option, add the dish name exactly as written on the meal product.
  3. Set the variant price to the per-plate price.
  4. Save. Every plan page that points at this product picks up the new option in all of its dropdowns.

If a plan page uses Menu item blocks rather than variants, add a matching block instead. The plan page prefers the variant list when the Meals product setting is filled, and falls back to blocks when it is empty.

Update a product

Price per plateProduct → Variants → PriceChange it on the plan product; that is the number the cart charges. The meal product price only shows in the menu list.
Dish nameProduct title or variant titleRenaming a variant breaks any Menu item block that matched the old name — update both.

Remove a product
  1. Remove the variant or block first. Deleting a product that a plan page still references leaves a dropdown option that cannot be added to the cart.
  2. Check the plan pages: open each one and confirm the dish is gone from every dropdown.
  3. Remove it from the collection, then archive or delete the product in Products.
  4. If the product is referenced by an image or a link in a section, clear that link so it does not 404.
Archive before deleting. Set the product to Draft or Archived for a week first. Orders and reports keep pointing at the product ID, and an archived product can be restored if the dish comes back next season. Deleting is permanent.
Remove a whole plan

Removing a plan (for example retiring the 5-meal plan) touches more than the product:

  • Delete or unpublish the plan product.
  • Delete the plan page in Online Store → Pages.
  • Remove the plan card from cm-plans and from the Related plans blocks on the other plan pages.
  • Remove it from the header menu and the footer links.
  • Delete templates/page.N-meal-plan.json and templates/product.N-meal-plan.json if you are not bringing it back.
  • Drop the handle from plan_handles in sections/cm-build-box.liquid if you remove a box-builder plan.
Verify a product change
  • The product is Active and published to the Online Store
  • Handle matches every link that points at it
  • Template suffix is correct — blank for a meal, N-meal-plan for a plan
  • Photo is square and shows in the menu card
  • Calories, protein, carbs, fat are filled
  • Allergens and diet tags are filled
  • The dish appears in the plan page dropdowns
  • Adding it to the cart produces a line with the right price
  • Removing it leaves no broken dropdown option behind

GSAP animations

snippets/gsap-animations.liquid loads GSAP, ScrollTrigger, ScrollSmoother and SplitText only when Theme settings → Animations → GSAP animations is on. It also respects prefers-reduced-motion: when a visitor asks for reduced motion, the animation class is never added and content renders immediately.


{%- if settings.animations_gsap -%}
  <script>
    if (!window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
      document.documentElement.classList.add('gsap-pending');
    }
  </script>
  {{ 'gsap-animations.css' | asset_url | stylesheet_tag }}
  <script src="{{ 'gsap.min.js' | asset_url }}" defer="defer"></script>
  <script src="{{ 'gsap-animations.js' | asset_url }}" defer="defer"></script>
{%- endif -%}
A safe timeout is built in. If the animation script fails to load, a 2.5-second fallback removes the gsap-pending class so content is never left hidden.

Performance & Accessibility

Performance
  • Images render through image_url + image_tag with explicit widths and sizes, so the browser downloads the smallest usable file.
  • Everything below the fold is lazy-loaded; hero imagery is eager with fetchpriority="high".
  • Scripts are deferred and section-scoped. Maps, carousels and the wheel load only on pages that contain them.
  • Fonts are preloaded and use display=swap.
  • No app scripts, no jQuery, no third-party tracking by default.
Accessibility
  • Semantic landmarks and heading order on every template.
  • Accordions use native <details> / <summary>, so they work with a keyboard out of the box.
  • Visible focus rings (:focus-visible) on buttons, links and form fields.
  • Live regions announce cart and delivery-checker results.
  • Decorative images are hidden from screen readers; content images require alt text.
  • Reduced-motion preference disables scroll animation.
Before launch: run Lighthouse on the home page, one plan page and one product page. Replace demo images with compressed WebP/JPG under 300 KB, and keep the hero at one image rather than a slideshow.
